cb2 playground

cb2 stands for Cryptographically Bound tokens, version 2, and the format is also called BRACE: Bound, Rule-checked, Authenticated, Committing Envelope. This is the cb2 token library, compiled to WebAssembly and running on this page. Nothing you type leaves the browser. Build a token on the left, step by step; every button runs a playground command, and the transcript on the right shows the command and what the library answered, so the same session works in the command-line playground. Scenarios

Each one fills the forms below and runs them, so you can see a complete case and then change any field.

1 Keys

A local key seals tokens that only holders of the same key can open. A signing pair signs tokens that anyone with the public half can verify. A key id is bound into the token's footer, so a verifier can pick the right key before verifying anything.

Change a key id

A freshly generated key carries its own id (the kcb2.lid or kcb2.pid of the key). Clearing it leaves the token without a footer. Keys come and go as kcb2 strings in step 7.

2 Issue a token

The registered claims become the JSON payload; identifiers are compared byte for byte and may not contain invisible or look-alike characters. Times accept +3600 (seconds from now), Unix seconds or RFC 3339.

Custom claims

namevaluetype

A raw token carries any bytes. The footer travels in the clear but is authenticated; the implicit assertion is authenticated but not sent, so both sides must know it.

3 The token

Edit it freely: one changed character makes it invalid, with no further detail. The parts below are read without verifying anything.

4 Verify

A verifier states what it expects before reading the token. Rules that name no issuer and no audience are refused before the token is touched. Claim verdicts are given only after the token authenticated.

5 Key lookup by kid

A verifier that holds several keys reads the kid from the footer without verifying anything, picks the key with that id from step 1, and only then verifies. An unknown kid is refused before any cryptography. A forged kid picks the wrong key, and the token is invalid, because the footer is authenticated too.

Forge the kid

Rewrites the footer of the token in step 3 to name another key, without touching the body. The kid is unverified, so the lookup follows it; the verification does not.

6 Key wrapping

A local key wrapped under another local key becomes a kcb2.local-wrap string that can be stored or sent. Only the wrapping key unwraps it, and one changed character makes it invalid. The unwrapped key is the same key: compare the kcb2.lid in step 1.

7 Import and export keys

A key leaves the session as a kcb2 string. A kcb2.local or kcb2.secret string is the key itself and stays private; a kcb2.public string is the verifying half of a signing pair, the one to hand to verifiers. The string carries the key bytes only: an imported key gets its default key id back, so a script exported from the whole session restores custom ids with a kid line of its own.

8 International text

Identifiers (iss, sub, aud, jti and claim names) are UTF-8 in any script, compared byte for byte, with no invisible or formatting characters. Type anything, or try one of these.

9 Heavy load

Many requests against one resource, run here in the browser, to show that the time per request stays flat and every answer stays right. 256 users each hold their own token (and, for bound tokens, their own client key pair), and every hundredth request is an attack whose verdict is checked too: a changed character, an expired token, a token under another key, a replayed proof or a proof for another target. The run has its own keys and its own copy of the library, apart from the session above, and runs on one browser thread. The browser's clock is coarse, so the page times batches of about 40 ms and divides.
